项目与故事

项目名只用于任务书标题，建议用英文字母、数字、下划线或短横线。

人物设定 · 固定身份

姓名、发色、瞳色等身份特征分开写，便于 LLM 区分角色。留空的字段由故事自行决定。

参考资料 · 按需展开填写

提供灵感，LLM 会按剧情改编组合，不会整段照搬。均可留空。
生成参数 · 画布 / 采样 / 数量
默认值对应 Anima-Turbo（8–12 步、CFG 1）。若使用 Anima-Base / Aesthetic，建议 Steps 30–50、CFG 4–5；换成其他模型时按该模型的推荐值设置。

LoRA 触发词管理

逐行添加 LoRA 及其触发词；点「由 LoRA 生成质量词」会自动拼接进 quality_prefix。生图时如需单独设置强度，请在各 LoRA 行补一句备注。

quality_prefix · 每张图固定追加

会原样拼在每格提示词最前面（含 LoRA 触发词与固定风格词）。建议使用英文；自行填写的中文也会原样保留。

负面提示词 Negative prompt

在生图平台单独填写，不会进入每格提示词。

生成任务书

任务书包含：LLM 角色与规则、分镜景别规则、输出协议（大纲 + 每章 JSON）、提示词组装规则、你的全部输入、多轮对话流程与种子表。
点击「生成任务书」预览内容。

多轮对话脚本

把任务书发给任意 AI 后，按顺序复制下列指令，每轮只生成一章。

种子表

第 N 张使用「Seed 基数 + N − 1」。基数设为 -1 时每张随机，忽略本表。

这个工具是什么

它复刻 AnimaComicStudio（Butako11）的长故事提示词设计，但把「内置 ComfyUI 引擎」换成「任务书文件 + 任意 AI」：

  • 原项目：网页填表 → 后端把规则和输入打包成请求 → 内置 ComfyUI 节点调用 DeepSeek 生成 JSON → 同一节点直接采样出图。
  • 本工具：网页填表 → 生成一份自包含的 Markdown 任务书 → 你把它发给任意 AI（在线服务或本地模型皆可）→ AI 按多轮流程逐章输出 JSON → 每格的 prompt 字段喂回本仓库的流水线出图。

协议（角色一致性、服装状态继承、分镜表先行、分层校验思路、提示词组装顺序）与原项目 ComfyUI-Anima-Story 节点组一致，并按「纯对话、无代码兜底」做了适配：最终英文提示词由 AI 直接给出，连续性靠每轮的 previous_state 复述维持。

使用步骤

  1. 在「创作工作台」填好故事、人物、生图参数，切到「任务书与对话脚本」点生成任务书，下载 .md。
  2. 把任务书整份发给任意 AI（网页版 ChatGPT / Claude / 本地 Ollama 等都行）。建议上下文长度 ≥ 32768、Temperature 0.3；支持 JSON mode 的模型可开启。
  3. 第一轮先要故事大纲，确认满意后再按「多轮对话脚本」逐章要 JSON。
  4. 把每章的 JSON 存成本地 .md（格式见仓库里的 示例_第1章.md），到流水线标签页 ② 上传出图。

使用建议

  • 能力有限的小模型：每章设 5–10 张，故事以单人或双人互动为主，避免一格多人复杂互动。
  • 输出被截断：回复「继续」让模型接着输出；不要重新发送整章指令。
  • 某章 JSON 缺字段或帧号错误：把具体错误发回，例如「第 3 章缺少 panels/11/participants，请只重新输出第 3 章完整 JSON」。
  • 人物串色/外观漂移：在「AI 工作设定」里加一句「每格开头先复述每个出场人物当前的外观状态」；根本约束仍是第 7.3 节固定身份。
  • 先小规模验证：第 1 章出图满意，再继续后续章节，避免全文返工。

与原项目设计的对应关系

  • AI 工作设定 / 故事 / 人物 / 参考资料 / 生图参数 ← 原项目创作工作台全部输入项
  • LoRA 触发词与 quality_prefix ← 原项目「模型与 LoRA」页的触发词管理（此处不管理工作流模型文件，只管触发词）
  • 七阶段流水线（大纲 → 角色绑定 → 分镜表 → 章节核对 → 详细展开 → 中译英 → 逐张渲染）→ 压缩为任务书第 5 节的两轮协议：先大纲，再每章「分镜表 + 自检 + 详细 panels」
  • 中译英阶段 → 由「绘图字段必须英文」的硬规则代替，让 AI 直接写英文
  • 程序化提示词组装 → 任务书第 6 节组装规则，LLM 直接产出最终 prompt
  • manifest / 帧指纹续跑 → 第 9 节连续性规则：previous_state 复述 + 已完成章节不改写
